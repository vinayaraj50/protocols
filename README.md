# protocols

Welcome. You are in the right place.

This repository is a clean, safe home for technical protocols: clear step-by-step guides for important work.  
Think of it as an operations playbook with fewer surprises and more calm.

## Why this repository exists

- Keep critical procedures in one trusted place.
- Make protocols easy to read for every team member.
- Reduce risk by using repeatable, reviewed steps.
- Help people move fast without breaking things (or their weekend).

## What this repository is

- A collection of **safe technical protocols**.
- A place for practical instructions and guardrails.
- A fresh baseline after history sanitization and cleanup.

## What this repository is not

- Not a single giant document.
- Not the place for deep implementation details in the root README.
- Not a mystery puzzle game.

Detailed technical documentation belongs in each protocol’s own folder.

## How to use this repo

1. Open the protocol folder you need.
2. Read the protocol from top to bottom before running anything.
3. Follow steps in order.
4. If something is unclear, open an issue or PR with a suggested fix.

## Writing style for protocols

- Use short sentences.
- Use simple English.
- Use numbered steps for actions.
- Say what can go wrong and how to recover.
- Never include secrets, tokens, or private keys.

## Contribution checklist

1. Put new protocol content in the correct folder.
2. Add clear purpose, inputs, outputs, and rollback steps.
3. Keep examples realistic and safe.
4. Request review before merge.

## Final note

Good protocols are boring in the best way: predictable, reliable, and drama-free.  
If a protocol needs a decoder ring, we rewrite it.
